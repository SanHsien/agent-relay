## 實測中發現並修正的 bug（Phase 1 起就存在）

C 的回信一開始沒送到指揮者，machine-b 的 `relay.log` 記錄：

```text
dispatch sync failed: git pull --rebase --autostash --quiet failed: error: could not apply d35fb8b... relay: claude-code dispatch …9b3fc2 -> ok
CONFLICT (file location): mailboxes/claude-code/new/….json added in origin/mailbox inside a directory that was renamed in HEAD
```

- **原因**：machine-b 把 `claude-code/new/` 裡最後一封信 ack 到 `done/`。git 的 directory rename 偵測把這當成「`new/` 整個改名為 `done/`」，於是指揮者同時寄到 `claude-code/new/` 的 accept 通知被判為位置衝突，rebase 失敗並被 abort。
- **修正**：`gitsync.pull` 加上 `-c merge.directoryRenames=false`（commit `7396db1`）。
- **回歸測試**：`TwoMachineGitTests.test_ack_of_last_new_message_and_concurrent_mail_do_not_conflict`。拿掉修正時這個測試會紅（SyncError），加回修正就綠。
- 修正後 machine-b 再執行一次 `relay sync`，C 的回信就送到了。
