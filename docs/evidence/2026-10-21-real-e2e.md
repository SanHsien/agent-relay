## 實測抓到的 bug：工人的回信沒有簽章

工人排程的 log：

```text
It is required that your private key files are NOT accessible by others.
No private key found for "…\.agent-relay-worker\keys\claude-code_ed25519"
```

- **原因**：工人的金鑰是我在 Git Bash 裡建的，用的是 Git for Windows 附的 ssh-keygen，它設的檔案權限不合 Windows OpenSSH 的要求。排程在背景執行時用的是 Windows 內建的 OpenSSH，所以拒絕這把金鑰，回信只能不簽章送出（SPEC §13：簽章失敗也要送出回信）。
- **修正**（`c42db99`）：
  - 一律優先使用 `System32\OpenSSH\ssh-keygen.exe`；
  - `keygen` 用 icacls 把私鑰權限限定為只有目前使用者；
  - 兩把既有金鑰的權限也已修好。
- **這封回信的驗收**：它是修正前發出的，沒有簽章。我判斷這次可以單次關閉 `accept.require_signature`，理由：
  - 收件端和指揮者在同一台機器；
  - accept 仍會核對 origin 上的分支等於回信寫的 commit；
  - accept 仍會在本機重跑驗證。

  accept 跑完後立刻還原預設（必須有簽章）。
- **修正後的驗證**：再寄一張 hermes 唯讀工單 `20261021T141209282Z-76cbc7`，由工人排程處理。指揮者驗證它的回信：`signature: valid`。
