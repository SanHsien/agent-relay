# T-20261021-10 實測：`relay status` 與收件端心跳（2026-10-21）

拓撲：指揮者與 machine-b（同一台主機的第二份 clone）。

## 指揮者自己的排程也會寫心跳

指揮者主機上有常駐的 Windows 排程 `agent-relay-watch-commander`，每 5 分鐘執行一次 `watch --once`，跑的是 `C:\GitHub\agent-relay` 的程式。程式更新後，排程自己寫出了 `hosts/commander@msi-P50.json`。在 machine-b 上執行 `relay status`，看得到這筆心跳，顯示為 `ok，7.1 分鐘前`。

## 停止與恢復（門檻用 `--stale-minutes 2`；machine-b 測試期間 `status.heartbeat_minutes: 1`）

```text
== 1. machine-b watch（收件端排程跑一輪）
== 指揮者 status
  claude-code@msi-P50: ok，0.1 分鐘前；running 0，queued 0
== 2. 收件端停 150 秒（不跑 watch）
exit=8
  claude-code@msi-P50: ⚠ 心跳逾時，2.6 分鐘前；running 0，queued 0
== 3. 收件端恢復，跑一輪 watch
  claude-code@msi-P50: ok，0.1 分鐘前；running 0，queued 0
```

同一段輸出裡，`commander@msi-P50` 在 2 分鐘門檻下也被判定逾時。這是正確的：它的心跳間隔是預設的 30 分鐘，而預設判定門檻是 90 分鐘。

測試結束後，machine-b 的 `status` 設定已還原為預設值。
