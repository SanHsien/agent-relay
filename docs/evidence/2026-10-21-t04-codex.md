## 第 1 封：發現使用者設定會撐開沙箱（`20261020T173405705Z-78131d`）

- 結果：status ok，relay commit `c63e976`，閘門 green，已推送。
- **但兩個反例都寫成功了**：`calc-demo/.git/hooks/codex-probe` 和 `calc-demo/codex-outside-probe.txt` 都出現。
- 原因：主人的 `~/.codex/config.toml` 有下面這段設定，而測試區正好在 `%TEMP%` 底下。

  ```toml
  [sandbox_workspace_write]
  writable_roots = ['C:\Users\SanHsien\AppData\Local\Temp']
  ```

- 同一份設定還有 `sandbox_mode = "danger-full-access"`。CLI 的 `--sandbox workspace-write` 會蓋過它，但 `writable_roots` 不會被蓋過。
- 結論：relay 不能依賴使用者的 codex 設定。

**修正**（commit `390cf16`）：每次 codex 派工都附加下列三個設定。

```text
-c sandbox_workspace_write.writable_roots=[]
-c sandbox_workspace_write.exclude_tmpdir_env_var=true
-c sandbox_workspace_write.exclude_slash_tmp=true
```

另外，每次嘗試的實際指令（prompt 不列入）寫進 `runs/<id>/argv.json` 和回信的「指令」行。探測檔已刪除。

## 第 3 封與重試：指令證明與限流行為（`20261020T174401797Z-f99192`）

`argv.json` 記錄的實際指令（路徑縮寫）：

```text
codex.exe exec --json --sandbox workspace-write -o …\runs\<id>\last.json -C …\.relay-worktrees\<id>
  -c sandbox_workspace_write.writable_roots=[] -c sandbox_workspace_write.exclude_tmpdir_env_var=true
  -c sandbox_workspace_write.exclude_slash_tmp=true
```

這次 codex 回 `exceeded retry limit, last status: 429 Too Many Requests`，5 小時窗口已到 90%。之後應主人要求以 `--force` 重試一次，結果相同。relay 的處理：

- 嘗試記為 `codex：failed（rate-limited）`；
- 信件明寫 `--run codex`，所以沒有可改派的 runtime（只有 `runtime auto` 才會改派，SPEC §10）；
- 工人沒有正常結束，所以不 commit，也不推送；
- 照常回信並 ack。

## 結論

- codex 能在 worktree 內施工，也能自己跑驗證。
- relay 代為 commit，閘門與推送都正常。
- 釘住設定之後，`workspace-write` 只能寫 worktree：主 repo 的 `.git/hooks` 和 worktree 外都寫不進去。
- 已知限制：讀取不受限，這點和 hermes 相同（SPEC §7）。
